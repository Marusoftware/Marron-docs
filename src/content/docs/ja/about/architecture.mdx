## 全体構成

Marron は中央管理プレーンである **Marron Core** と、必要に応じて配置する軽量エージェント **Marron Jam**、機能を追加する **プラグイン** から構成します。

## Marron Core

Core は管理プレーンとして、次の機能を統括します。

- Web UI、API、認証・認可、テナント分離
- Resource Registry と Resource 間の Relation
- Desired State / Observed State の管理
- Workflow、Plan / Preview / Apply、承認
- プラグイン管理、監査ログ、バックアップ
- Jam の登録、権限付与、状態同期

初期実装はモジュラーモノリスを基本とします。モジュール境界と API を明確にし、負荷・可用性・セキュリティ上の理由が生じた機能だけを独立プロセスへ分離します。

## Marron Jam

Jam は完全に任意の軽量エージェントです。導入できない機器や導入したくない機器があっても、Marron の利用を妨げません。

想定する機能は、機器発見、テレメトリ収集、ローカル集約、許可されたタスク実行、Heartbeat、Capability Report、Jam 間通信です。機器の対応能力を報告し、未対応の操作を対応済みとして扱わないことを原則とします。

Jam の自律性は、例えば次の段階で制御します。

| モード | 動作 |
| --- | --- |
| Observer | 監視・収集を行い、変更操作は行わない |
| Worker | 明示的に許可されたタスクを実行する |
| Autonomous | ポリシーで定めた範囲内で判断・実行する |

## Jam 間 P2P

Jam 間の P2P ネットワークにより、Core を経由する通信を減らし、ローカル集約、状態共有、障害時の継続性を高めます。VLAN、サブネット、拠点をまたぐ構成を想定し、直接接続できない場合は中継ノードを利用できる設計とします。

すべての Jam が常時相互接続する必要はありません。必要性やポリシーに応じて接続先を選びます。Core は管理上の権威を保持し、P2P は Core の代替ではありません。

ネットワーク分断中は、事前許可された監視や限定操作を継続できます。競合する変更を防ぐため、操作リース、フェンシング、冪等性、必要に応じた Quorum を設計課題とします。監視継続と、影響の大きい変更操作の許可は分けて扱います。

## プラグイン

プラグインの候補カテゴリは Compute、Network、Storage、Provisioning、Monitoring、Workload、Integration です。Core 内モジュールから開始し、必要に応じて外部プロセス型へ拡張します。

プラグインは Core が提供する API / インターフェースを通じて操作し、データベースを直接変更しません。Ansible などの既存ツールは、任意の構成バックエンドとして連携できますが、必須依存にはしません。

## 配置と可用性

初期構成は単体 Core + 複数 Jam を基本とします。将来は Core の HA / クラスタ構成を選択可能にします。Core の冗長化と、管理対象ワークロード自体の冗長化は別の概念として扱います。

Core 停止中も、既存サービスや事前許可された Jam のローカル機能が可能な限り継続し、復旧後に差分を同期できることを目指します。

## 今後決定する事項

P2P の通信プロトコル、NAT 越え、中継方式、Jam の鍵・ID ライフサイクル、Quorum / Lease / Fencing の具体方式、プラグインの配布・署名方式は実装段階で確定します。
