## 監視と通信量

監視のためにネットワーク通信量を不必要に二重化しないことを重視します。イベント通知、差分同期、Jam 側でのローカル集約、適応的ポーリング、サンプリング、エージェント単位の通信量・頻度制限を組み合わせます。

P2P によるローカル集約を利用し、すべてのデータを常に Core に中継する必要がない構成を目指します。

## Discovery / Management / Automation

この3つは独立した段階です。

- **Discovery:** 対象を発見して情報を収集する
- **Management:** Marron が管理責任を持つ対象として登録する
- **Automation:** 許可された範囲で操作を実行する

自動発見した機器を、利用者の意図なく変更可能な状態にしません。

## 自動化レベル

| レベル | 動作 |
| --- | --- |
| Manual | 情報収集と計画まで。実作業は人が行う |
| Approval | 承認を得てから変更を実行する |
| Automatic | ポリシーの範囲内で自動実行する |

設定は Resource、グループ、階層ごとに適用でき、継承と上書きを可能にします。ただし、上位のセキュリティ制約や明示的な拒否を下位設定で解除することはできません。

## Plan / Preview / Apply

変更操作は原則として次の手順を通します。

1. **Plan:** 変更内容と依存関係を計画する
2. **Preview:** 差分、影響範囲、実行可能性を検証して提示する
3. **Approval:** ポリシーに応じて承認を得る
4. **Apply:** 許可された変更を実行する
5. **Verify:** 実行後の状態を再取得し、結果を確認する

承認は特定の Plan バージョンまたはハッシュに結び付けます。承認後に計画内容が変わった場合は、必要に応じて再承認します。失敗時は完了済みステップ、補償・ロールバックの可否、復旧手順を記録します。

管理対象から外された Resource の設定を、Marron が自動的に元へ戻すことはしません。

## 人による作業の管理

人が実施する作業も Marron の運用モデルに含めます。作業チケットには目的、対象 Resource、影響範囲、手順・チェックリスト、担当者、承認者、予定・実績時刻、作業前後の状態、結果、添付資料、検証結果を記録します。

想定する状態:

- Draft
- Planned
- Approved
- In Progress
- Verification
- Completed
- Failed
- Cancelled

作業開始を登録すると、Marron は対象範囲と作業中であることを把握します。メンテナンス中は関連する自動操作や通知だけを適切に抑制し、監視全体を停止しません。作業範囲外の重大障害や予期しない影響は引き続き検知します。

## 変更履歴

誰が、いつ、何を、どの計画・承認に基づいて実行したかを監査可能にします。手動作業と自動実行を同じ Resource の履歴に関連付けます。
