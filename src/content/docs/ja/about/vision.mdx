# Marron とは

Marron は、物理インフラから仮想化基盤、ネットワーク、ストレージ、コンテナ、アプリケーションまでを一元的に把握・管理する、拡張可能なインフラ管理プラットフォームです。

最初は小さく単体で動かし、必要に応じて管理対象、管理範囲、自動化の範囲、冗長化の構成を段階的に広げられることを重視します。特定の大規模オーケストレーション基盤や外部サービスを必須にせず、個人環境から組織のインフラまで導入規模を選べる設計を目指します。

## 設計原則

- **段階的な導入:** 発見・可視化だけから始め、必要な対象だけを管理し、準備ができた範囲から自動化します。
- **統合された資源モデル:** 機器、ネットワーク、仮想マシン、ストレージ、サービスを共通の Resource と関係性で扱います。
- **実態と設計の分離:** あるべき状態 (Desired State) と観測された状態 (Observed State) を分け、差分を明示します。
- **安全な変更:** 変更は Plan、Preview、承認、Apply、検証の流れで実施し、操作履歴を残します。
- **人と自動化の共存:** 人が作業中であることも管理対象とし、作業計画やメンテナンス範囲をシステムに伝えられます。
- **低オーバーヘッド:** 差分同期、イベント通知、ローカル集約、適応的なポーリングを用い、監視のための通信を抑えます。
- **拡張可能性:** Core は当初モジュラーモノリスとし、必要な部分だけを後から独立サービス化できるようにします。
- **オープンな連携:** Jam が存在しない機器も、SSH、SNMP、Redfish、IPMI、ベンダー API などで扱えるようにします。

## 管理の段階

| 段階 | 意味 |
| --- | --- |
| Discovery | 機器やサービスを発見し、情報を収集する |
| Management | Marron が管理対象として責任を持つ範囲を選ぶ |
| Automation | ポリシーで許可された操作を人または自動処理で実行する |

発見されたものが自動的に変更可能な管理対象になるわけではありません。利用者が対象と権限を明示的に選択します。

## 初期リリースの考え方

まずは単体 Core と複数 Jam、統合 Resource モデル、インフラマップ、手動・承認付き操作、バックアップとリストアを優先します。Core HA、複雑なクラスタ制御、課金、すべての機器に対する自動構成は初期要件にしません。
